## 00:00 开场（0:00 - 1:00）

【画面】标题卡

> 订单状态 创建支付发货。/ 普通并发消费 / 可能先收发货后收支付。/ 今天顺序消息治它。

## 01:00 分区顺序（1:00 - 4:00）

【画面】全局顺序(单队列崩) vs 分区顺序(同key同队列)

> 误区：队列保证先发先到。/ 错。只保证分区顺序。/ 全局顺序=单队列单线程 / 吞吐崩不用。/ 要的是订单维度有序。

【留存锚点】"RocketMQ 保证哪种顺序 / 分区顺序 同队列内 / 评论区扣 8。"

## 04:00 Selector（4:00 - 7:30）

【画面】orderId hash % 队列数 → 固定队列

> send 传 MessageQueueSelector。/ orderId hash 对队列数取模。/ 相同 orderId 永远同队列。/ 创建支付发货进同队列排好。

## 07:30 Orderly（7:30 - 10:30）

【画面】队列加锁串行消费

> 消费用 MessageListenerOrderly。/ 对单队列加锁串行。/ 返回 SUCCESS 提交 / 重试暂停该队列。/ 其他队列不受影响。

## 10:30 实战（10:30 - 13:00）

【画面】订单流转 CREATED→PAID→SHIPPED

> 按 orderId 路由固定队列 / 顺序消费。/ 下游永远先创建再支付后发货。/ 审计风控物流不乱。

## 13:00 收尾

【画面】总结卡

> 今天：分区顺序、Selector 路由、Orderly 加锁。/
> 明天 Day9 / 延迟消息 30 分钟关单。/ 点赞订阅。
