## 01:30 四大角色（1:30 - 5:00）

【画面】四角色关系图：Producer/Consumer/Broker/NameServer

> RocketMQ 四个角色 / 正好对应一个邮局。/
>
> Producer 寄件人 / Consumer 收件人 / Broker 邮局仓库 / NameServer 通讯录。/
>
> 最关键一点：/ 寄件人从不直连邮局实体地址 / 先翻通讯录问"Topic 在哪个 Broker"。/ 所以邮局换 IP、扩容 / 上下游无感。/ 这就是解耦。

【留存锚点】"NameServer 挂了已建连的收发通不通 / 通，只是不能发现新路由 / 评论区扣 1。"

---

## 05:00 Topic 与 MessageQueue（5:00 - 8:00）

【画面】Topic 下 4 个队列分给 2 个消费者的图

> Topic 是一级分类 / 订单、短信各一个。/ 别用 Tag 当分类 / 那是错的。/
>
> MessageQueue 是 Topic 里的格子 / 默认 4 个 / 等于最多 4 个人同时取信。/ 你起 8 个消费者？/ 多 4 个分不到格子干瞪眼。/
>
> 记住一句 / 队列数 = 最大并行消费数 / 后面讲积压救命用。

## 08:00 环境搭建（8:00 - 11:00）

【画面】终端录屏 `docker compose up -d` + `boot success`

> 环境一行命令。/ 仓库自带 docker-compose。/ `docker compose up -d` / 看到 boot success 就起好。/
>
> 端口 9876、10911。/ autoCreateTopicEnable=true / 发消息自动建 Topic / 零配置。/
>
> 一个坑先说：/ 容器里 Broker 默认通告容器 IP / 宿主机连不上。/ 我们的 broker.conf 设了 brokerIP1=127.0.0.1 / 本地必设 / 否则测试必超时。

## 11:00 Hello World 裸 API（11:00 - 15:00）

【画面】IDE 录屏 Day01QuickStartTest

> 不套 Spring / 裸 API 看清三件事。/
>
> 第一 / Producer Consumer 都得 start 才干活 / shutdown 才释放。/
> 第二 / 消费者注册监听器 / 后台线程自己拉 / 你别写轮询。/
> 第三 / 返回 CONSUME_SUCCESS / Broker 才认你消费完。/
>
> 跑测试 / 绿灯 / received=Hello RocketMQ / 你的邮政系统通了。

【留存锚点】"队列数为什么等于并行度 / 评论区打 队列。"
